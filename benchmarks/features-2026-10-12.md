## API review and decisions

- `WithStop`: owned and borrowed policies remain distinct. Borrowed policies
  cannot produce an owned shared view, and replacing a policy explicitly bypasses
  inner callbacks. No fields are added to ordinary pulses. Make it unconditional
  in core and the tracker re-export.
- `TryStages` / `RunError`: retain the explicitly fallible planning contract and
  the distinction between planning and work errors. `Stages` remains the normal
  library integration path. The strict API adds no dependency or tracker state;
  expose it without a Cargo gate.
- Snapshot JSON: the writer takes `core::fmt::Write`, works without std, and
  retains schema 2 and its decimal-string count encoding. No serializer
  dependency or per-node state. Make it unconditional.
- `ProgressSmoother`: `new` / `Default` and `display_fraction` keep state in a
  separate caller-owned object, with caller-supplied time. Existing tests cover
  revised totals, cancellation/failure, bounded extrapolation, stalls, equal or
  earlier timestamps, and large totals. Keep the stable `smooth` opt-in: its
  22,524 IR lines exceed the tracker default budget of 22,000.
- Stage suggestions: no extra public signatures, but the grouping heuristics
  and generated advice still need flexibility across representative workloads.
  Use `experimental-stage-suggestions`, off by default. Its 37,667 IR lines
  exceed the diagnostics default budget of 35,000. Document the experimental
  contract explicitly; a feature-name prefix alone is not a compatibility rule.
- Keep `std` for the tracker synchronization backend and `callback` for its
  per-node dispatcher slot and conditional checkpoint dispatch.

Default IR budgets are unchanged. Historical benchmark records retain the
feature names used at their recorded revisions.

## Final feature configuration

Source: `be613b9f0a6f072c62ab25f17166492856f98d25`. Same command, toolchain,
host and sampling method as the baseline. Core check/debug/release medians
change from 0.065/0.116/0.199 s to 0.079/0.143/0.212 s. This is a small absolute
compiler cost for always-available adapters and the strict runner; it is not a
claim that application builds are unchanged. Caller IR stays at 88 lines per
`Stages::run`. All default IR budgets pass unchanged. Optional smoothing and
stage grouping still exceed their corresponding default budgets.

## Migration

- Remove `adapters` and `checked` from `how-far` dependency feature lists.
- Remove `adapters` and `json` from `how-far-along` dependency feature lists.
  JSON remains available even with `default-features = false`.
- Replace `how-far-really/stage-suggestions` with
  `how-far-really/experimental-stage-suggestions` when grouping is wanted.
- `how-far` has no features. `how-far-along` defaults to `std`, with optional
  `callback` and stable `smooth`. `how-far-really` defaults to no features.
- No function signatures or runtime algorithms change. This is a pre-publication
  manifest migration: the removed feature names are not retained as empty aliases.
